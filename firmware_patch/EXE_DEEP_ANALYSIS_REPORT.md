5. **Key Hash Mismatch**: If multiple key hashes exist, there might be a
   fallback verification path that accepts different signatures

6. **Rust Binary Patching**: Patch the EXE's signature verification routine
   to always return success (NOP out the check)

### Critical Question:

Does the EXE verify signatures BEFORE sending data to the device,
or does the DEVICE verify signatures after receiving the data?

If verification is DEVICE-SIDE (MCUboot), then patching the EXE alone
will not help - we need to bypass MCUboot on the device itself.

If verification is EXE-SIDE (host tool), then simply patching the
verification function in the EXE would allow flashing any image.

The answer is likely BOTH - the EXE probably validates before sending,
AND MCUboot validates after receiving. The device-side validation is
the hard barrier that cannot be bypassed without the signing key.
